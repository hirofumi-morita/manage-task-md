# このフォルダでのAIエージェントの動き方

このフォルダは taskmd で管理しているタスク vault です。タスクは `tasks/` に1ファイル1件の Markdown で置かれ、状態は frontmatter の `status` で管理します。

## 基本ルール

- **頼まれたときだけ動く**。依頼されていないタスクに勝手に着手しない。
- **タスクの操作は taskmd の MCP ツールを使う**（`taskmd` サーバ）。使えないときは CLI の `taskmd` を使う。frontmatter を手で書き換えるのは最後の手段にし、書き換えたら `taskmd validate` を通す。
- **done にしない**。作業が終わったら `submit_for_review` で review に出し、人の確認を待つ。
- `## 作業ログ` は追記のみ。過去の行を書き換えたり消したりしない。

## 「T-0042 をやって」と頼まれたとき

1. `get_task` で中身を読む。`## 目的`・`## 受け入れ条件`・`## コンテキスト` とリンク先のノートを確認する。
2. `claim_task` で着手する。lease（作業中のロック）が付き、`runs/` に実行ログファイルができる。
3. 作業する。途中経過や判断の理由は実行ログファイル（`lease_run` のリンク先）の `## メモ` に書く。要所では `append_log` でタスクにも1行残す。
4. 作業が長引くときは `renew_lease` で lease を延長する。
5. 受け入れ条件を満たしたら、チェックボックスを `- [x]` にし、`submit_for_review` に結果の要約（何をしたか・成果物へのリンク・残課題）を渡す。
6. 進められない理由ができたら `set_status` で `blocked` にし、理由を `note` に書いて止まる。

## 「次のタスクを進めて」と頼まれたとき

`next_task` で1件だけ選び、上の手順で進める。終わったら次を勝手に始めず、報告して止まる。

## 「分解して」「inbox を整理して」と頼まれたとき

- 大きいタスクは `split_task` で子タスクに分ける。子タスクには目的と受け入れ条件を必ず書く。
- `inbox/` のメモは `create_task` でタスク化し、元のメモには作ったタスクのリンク（`[[T-0043]]`）を書き足す。メモ自体は消さない。
- 順番に依存がある場合は `depends_on` を設定する。未完了の依存があるタスクは自動で `blocked` になり、依存が終わると `ready` に戻る。

## ステータス

| status | 意味 |
|---|---|
| backlog | いつかやる。まだ着手対象ではない |
| ready | 着手できる |
| in_progress | 作業中（lease あり） |
| review | 作業完了、人の確認待ち |
| done | 完了（人が確認済み） |
| blocked | 止まっている（依存待ち・確認待ちなど） |
| cancelled | 中止 |
